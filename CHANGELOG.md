### Ninth round, second pass: git write allowlist, reports for the "by design" gaps, runner leftovers

- **Absent `.git/config.worktree` (high, reproduced by the verifier)**: only an existing one was locked, so the agent could create it (git reads it when `extensions.worktreeConfig` is set; `core.fsmonitor` / `hooksPath` / `sshCommand` there run on the host). An absent one is now an empty read-only file (a pin, removed at release). Specs: create, `rm` and `mv .git/config` onto it are refused, none is left on the host, an unsandboxed `git status` runs nothing.
- **Allowlist for the top level of a git directory**: a mount cannot refuse a new name in a directory git must write to (`index.lock`), so "safe by construction" is only true for the names git consults that can run a command (`config`, `config.worktree`, `hooks/`, `info/`, `commondir`, `modules/`, rebase / sequencer state, `worktrees/`, `remotes/`, `branches/`): those are mounts. For everything else `plan.GIT_WRITE_ALLOWED` lists what git writes itself; an existing name outside it is read-only; a NEW one is copied to the quarantine, removed and the project is marked when the run ends (`guard.git_audit`, also for submodule git directories and any new directory below `modules/`). The window between creation and the end of the run is stated in the README. I enumerated the consulted names from git's documentation (config files, hooks, attributes and filters, fsmonitor, credential helpers, editors, `gpg.program`, `alias.*`): all of them are configured in `config`, `config.worktree`, `hooks/` or `info/attributes`; content of allowed names (`objects/info/alternates`, `refs/replace`, `logs/`) is not audited, it is data to git. This is from reading, not a proof for every git version. Specs: a new `fsmonitor--daemon.ipc` and a new `evil/` directory are removed and mark the project, `MERGE_MSG` / `index.lock` stay, an ordinary commit marks nothing, an existing unknown `svn/` is read-only. 3 of the 4 new git specs failed against the previous commit (the fourth, an ordinary commit, passes there too).
- **Survivors listed by the verifier**: the `git://` userinfo, the validation of `guard_dirs` / `guard_files` / `secret_allow`, the 19 secret globs, the base64 key headers and the token length predicates were already pinned in the first pass (above); I re-checked that their specs exist and pass, I did not rerun the whole mutation set. New in this pass: `guard.QUARANTINE_DEPTH` (8) and `guard.UNLOCK_MAX` (5000) are named constants with exact specs (the copy stops at the depth and not one level later; a forced removal that may open 12 entries leaves a tree of closed directories and reports it, the real budget removes it; a 555 parent gets its mode back and the project directory keeps its own).
- **"By design" gaps, moved to a loud report with the changed lines (none is prevention, the agent has to be able to write these)**: the end-of-run notice shows up to six `- old` / `+ new` lines (cut at 72 characters, control characters replaced) for an edited small review file, so a changed `.nvmrc` or `.gitattributes` is readable at once; `init.gradle(.kts)` joined the list. `buildSrc/` and `build-logic/` (any depth) are recorded as a whole and a created / changed / deleted tree is an ERROR notice with the files and line counts. `node_modules/.bin` of the project and its workspaces (not dependencies', 500 entries) is compared by link target or hash; a regular file or a link leaving `node_modules` is an ERROR, an install-style link a warning, because an install changes it legitimately. Not covered, stated in the README: `.gradle/init.d`, included builds under other names, dependencies' own `.bin`. 23 of the first 25 specs in `tests/gaps_spec.lua` failed against the previous commit (2 pin behaviour that already held: a 555 parent and the constants).

Cause: the earlier runner removed a finished run's scratch tree with `vim.fn.delete`, which stops at the 0555 / 0000 directories the specs create and had already unlinked `.owner` first (directory order); the ownerless remainder then waited 24 h by age and failed again. A complete run and a killed runner (`round8_runner_spec`) leave none: counts before and after are in the results below. The old directories are removed by the 24 h age rule from tomorrow evening, or by you.

### Ninth round: git write mode bypasses (fix round, red-team findings)

- **`.git` rebuilt in git write mode (critical, reproduced by the verifier)**: `.git` was writable but not a mount point, so `mv .git .git.old && mkdir .git && cp -a .git.old/. .git/` followed by a planted `hooks/pre-commit` and `git config core.fsmonitor ...` left a host `.git` that ran the command on the next unsandboxed `git status`, with an empty release report (the sweep does not enter `.git`). Now every writable git directory, `modules/` and every submodule git directory (4 levels) is bound onto itself, so it cannot be renamed.
- **`.git/commondir` (critical)**: writing `../evilcommon` made the host git read config from another directory. `commondir` is now pinned (a private file holding `.`, bound read-only over the absent name; the empty mount point bwrap leaves on the host is removed at release) or locked when it exists. Submodule git directories too.
- **Same family, closed by reading git's behaviour and then by spec**: `rebase-merge/`, `rebase-apply/`, `sequencer/` (an `exec` todo line that a later `git rebase --continue` runs; the verifier wrote one but did not run a rebase, so this vector is closed but its exploit is not verified), `remotes/`, `branches/`, `worktrees/` are read-only when present and masked when absent. `hooks/` and `info/` are masked when absent. Cost: rebase, multi-commit cherry-pick, `am`, `worktree add` and `submodule add` fail inside the sandbox in this mode. The submodule lock now goes below the first level of `modules/`, which it did not before.
- **Mutation survivors that were real gaps (all demonstrated by the verifier, now killed; each mutant re-applied and failing in `tests/round9_spec.lua` or `tests/tables_spec.lua`)**: `git://` and `ftp://` user info kept a token (`and` for `or` in `strip_userinfo`); no spec for the validation of `policy.guard_dirs`, `guard_files` and `secret_allow`; about 19 default secret globs were not pinned (the table spec looped over the table it was testing; `tests/tables_expected.lua` now holds the written-out list and the last test compares it with `plan.lua`); the base64 EC, DSA, ENCRYPTED and PGP private key headers; the minimum length of every token format with a length predicate (at the minimum, one below, one above); the bounds of `policy.scan_depth` (1 and 32). 4 header mutants, 22 length mutants (`>=` to `>`, minimum plus one), the userinfo mutant and the guard_dirs validation mutant were each run and killed.
- **Hygiene (reproduced by the verifier, fixed)**: `tests/reaper.lua` could not remove a dead runner's directory holding 0555 / 0000 directories (`vim.fn.delete` stops at them, and the ownerless remainder waited 24 h and failed again): `remove_tree` opens each directory for its owner first and never follows a symlink; the end of a run uses it too. A complete run no longer leaves a `/tmp/xyno-run-*` directory (`round8_runner_spec` kills a nested runner on purpose and now removes that runner's directories by its pid; the count stayed at 144 across two runs and a full run). The runner killed a leaked `sh -c 'sleep 120; :'` but not its `sleep`: it now kills what the survivors started, found before they die. `leak_spec` waited for a `sleep 120` whose command line lacks the marker, so it could never see the survivor, and matched globally (flaky with concurrent runs): it uses a duration derived from its own pid and waits for it to be gone.
- **Not fixed, stated plainly**: the other survivors the verifier listed by reading (guard quarantine and delete-budget constants, `CONTENT_MAX_BYTES`, `plan.lua` hard link counts and flag arities, the bwrap error-text classifiers in `probe.lua`, the env value length 12) were not separated into equivalent and real mutants and have no new specs. The gaps the verifier called by design (`node_modules/.bin` executables, buildSrc and init.gradle sources, an edited `.nvmrc`, `.gitmodules` planted at the root is only swept) are unchanged. `.git/objects/info/alternates` and the like are writable in git write mode (see the README).
- **Baseline of the suite**: a full run on 2026-11-13 from a checkout outside /tmp, `XYNO_TEST_BASE` set: `RESULT passed=1101 failed=0 skipped=0 xfailed=1`. Counts differ by environment (a missing git or bubblewrap skips specs). A checkout under /tmp prints `SKIP all specs` and exits 0 with `passed=0`, which is not a pass; the README says so.
- Specs (`tests/git_write_spec.lua`, new describe) failed first against the previous commit (5 of 5 new ones), and four mutants (no `--bind`, no pin, `rebase-merge` removed from the list, depth 1) are each killed.

### Third hardening round

A second independent verification found the following; each has a spec in `tests/round3_spec.lua` or `tests/survivors_spec.lua` that fails when the fix is removed (mutation table below).

- **Hard links to `$HOME` credentials**: `ln ~/.ssh/id_rsa proj/x.txt` was readable in both home views; the credential list is now compared by inode with the project's multi-link files and the project name is hidden.
- **Secrets inside shown trees**: `$PATH` entries show their parent whole (`~/dotfiles/bin` shows `~/dotfiles/.ssh`); secret names are now hidden inside every shown tree (breadth first, bounded, package caches skipped). `policy.tree_secrets`.
- **Environment scrub by value**: known token formats and URL credentials are stripped under any variable name; new name shapes `*_KEY`, `*_DSN`, `*_SESSION`, `*_AUTH`, `JWT`, `COOKIE`, `BEARER`, `SESSION`, `AUTH`, `SERPAPI`.
- **Sockets**: searched everywhere below the project, also in `target/`, `node_modules/`, `.cache/`, `.git/` and deeper than 8 levels (own budget, noted in the plan when exhausted).
- **More secret names**: `.vault-token`, `.env~`, `.envs/`, `auth.json`, `rclone.conf`, `.terraformrc`, `.secret`, `.npmrc.bak`, `id_rsa.bak`, `id_ed25519_sk`, `wallet.dat`, `creds.json`, `oauth_token`, `sa.json`, `serviceaccount.json`, and by path `.docker/config.json`, `.config/gh/hosts.yml`, `.composer/auth.json`, `.m2/settings.xml`, `.gradle/gradle.properties`. - **Content scan**: a placeholder is judged on the matched token, not on the line (`TOKEN=ghp_... # example` was skipped); long lines are read; the preview counts what was not read (large, binary, by extension).
- **`~/.claude.json` copy**: API keys, e-mail and name, anonymous id, old history, MCP server `env`/`headers` and token-looking strings are removed.
- **kill -9 of Neovim**: the private copies and the socket directory are recorded and removed by the next launch.
- **Suite**: ignores the caller's `TMPDIR`; skips socket specs whose path exceeds `AF_UNIX`'s limit; works from a checkout under `/tmp`; a sandbox that does not start while bubblewrap works is a failure (not 90 skips); a hanging spec file is killed after 240 s and fails the run; the process-survivor check waits for the kill instead of a fixed 300 ms (the old flake). (`tests/hermetic_spec.lua`)

Behaviour changes: with the default allowlist view the agent no longer sees your global `~/.claude` settings, `CLAUDE.md`, plugins or other projects' transcripts (share chosen names with `policy.claude_share`); a token refresh inside the sandbox is not persisted.

Hardening after an independent red team. Each finding was reproduced by running it and now has a spec that fails when the fix is removed.

- **Environment**: bwrap starts with `env -i` and only the allowed variables; stripped secrets no longer exist in `/proc/1/environ` or any other process of the sandbox. `$NVIM` and `$NVIM_LISTEN_ADDRESS` are stripped. (`tests/env_spec.lua`)
- **Sockets**: `/run`, `/var/tmp` (and a real `/var/run`) are empty tmpfs; sockets named by `$SSH_AUTH_SOCK`, `$XDG_RUNTIME_DIR`, `$DBUS_SESSION_BUS_ADDRESS`, ... and sockets inside the project are hidden; the relay's own nvim RPC socket is stopped. New `policy.keep_run`. (`tests/sockets_spec.lua`)
- **Project secrets**: `.env`, `.env.*`, keys, `.npmrc`, `.netrc`, `credentials.*`, `secrets.*` ... hidden with empty read-only overlays; `policy.project_secrets`, `secret_files`, `secret_allow`; shown in the preview, approvable through the exception flow. (`tests/secrets_spec.lua`)
- **Symlinks**: links out of the project are listed in the preview with the readability of their target; `policy.symlinks = "refuse"` blocks the launch. (`tests/secrets_spec.lua`)
- **`$HOME` allowlist**: new option `home`, default `"allowlist"`; `"denylist"` restores the old view; `policy.home_allow`. A fake agent that needs `cargo`/`rustc`, `git` and the installed agent CLI run inside it. (`tests/home_spec.lua`)
- **Preview == argv**: the preview and the command line are rendered from `plan.ops`; the preview shows the base mounts, masked sockets, home view, env settings and, in full mode, the exact mount order. (`tests/preview_spec.lua`)
- **Exceptions**: approvals that cannot take effect (writable `<project>/.git`, unhide of a path nothing hides, env that is not stripped) are refused, not logged as approved; writable `/etc`, `/proc`, `/run/user`, shell startup files and symlinks that resolve there, `unhide /etc/shadow`, and `LD_PRELOAD`/`PATH`/`LD_LIBRARY_PATH` env exceptions are refused (`expert_exceptions = true` for the last). (`tests/exceptions_spec.lua`)
- **run()**: a missing agent is detected before anything is mounted or opened, with the sandbox on as well; `jobstart` failures close the new split and release the sandbox. (`tests/ui_spec.lua`)
- **Stray placeholders**: shared directories (`/tmp`, `/var/tmp`, `/run`, `/`, parents of `$HOME`) get no placeholders and are not mounted writable; placeholders of a dead Neovim are swept at the next launch; `tests/run.lua` fails when a spec leaves one in `/tmp`. (`tests/strays_spec.lua`)
- `wrap()` accepts `opts.env` (variables set on top of Neovim's environment) because bwrap no longer inherits the caller's.

Breaking: the command line now starts with `env -i NAME=value ... bwrap`; callers that looked for `bwrap` at index 1 must look for it after `env -i`. The default `$HOME` view is the allowlist.
